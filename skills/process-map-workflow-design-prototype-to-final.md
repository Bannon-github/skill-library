# Design a workflow as a process map: messy prototype, then clean final map

Source: [Business Process Mapping 101 (Step By Step Guide)](https://www.youtube.com/watch?v=zGB9SScvoQU) (Toni Debelic | OpsKings), YouTube-provided transcript.

**Goal:** Design or document a workflow by mapping it as a process map (inputs, ordered steps, decisions, stakeholders, outputs): start with a messy prototype map of the one process causing the most pain, share and iterate, then publish a clean final documentation map and keep it updated.

## Steps
1. Pick the single process that is currently causing the most trouble; skip choosing tools or depth for now. _Expect: One named process with a clear end output_
2. On paper/whiteboard/sticky notes, write the steps as simple boxes in sequential order (this, then this, then this, then the final output), noting inputs, decision points, and who is involved. _Expect: A rough v1 flowchart_
3. Expand it into a prototype map with collaborators: add context, links to tools, screenshots, problems, and improvement ideas without worrying about looks. _Expect: Messy map showing current state and possible future states_
4. Share it (photo or link), walk someone through it, collect comments, and iterate. _Expect: Revised map reflecting feedback_
5. Produce the final documentation map: only the as-is steps in order, decisions and parallel flows from trigger to final output, with notes and clutter removed. _Expect: Concise blueprint someone can follow day to day_
6. Move it into a shareable tool with access controls if needed, one tab per subprocess, and optionally add detailed docs/SOPs that expand each box. _Expect: Organised set of maps (the video's 'company brain')_
7. Revisit the map whenever the process changes or a better way is found, and update it. _Expect: Map stays current_

## Constraints
- Do not wait for the perfect tool or full detail; a v1 on paper is the goal (avoid analysis paralysis).
- Map one process per map/tab; a larger system is a collection of separate maps.
- The prototype map may hold current state and future ideas; the final map shows only what currently happens.
- Share the map early, even as a photo; collaboration is the point.
- A process map is a living document; revisit and update it as the process changes.
- Written SOPs come after the map, as detail layered onto it.

## Verification
- Final map has a clear start trigger, ordered steps, any decision points, and a single final output
- Final map contains no future/what-if notes
- At least one other person/agent has reviewed the map
